# HoopRogue · 战术大师

原创篮球肉鸽。没有技能卡，没有抽签变强——你只有一块战术板，
和一群会演戏的对手。杀戮尖塔的三件套被翻译成了篮球语言：

**定位：没有运气的博弈。** 读人、演戏、反演戏——克制矩阵就是牌桌，
体能就是筹码，对手的评分、演技和针对能力每一场都在涨。
这是整个项目栈的"策略"支柱。

| 杀戮尖塔 | 本作 |
|---|---|
| 每回合 3 点能量 | 每节 5 点体能，攻防共用 |
| 敌人意图公示 | 意图播报：对方下回合战术倾向（高级对手会演你） |
| 卡牌构筑 | 战术板构筑：升级战术 / 学新战术 / 球队特质，全部确定性 |
| 地图路线 | 赛前抉择：休整 / 情报 / 主场（二选一） |
| Boss 战 | 第 5 场 BOSS：30% 演戏 + 针对你的常用战术 + 先到 15 分 |

## 核心循环

每回合一次决策：读播报 → 在体能预算内选战术 → 概率公开结算。
克制矩阵完全公开（游戏内按 M 查手册），胜负取决于决策质量。

进攻七种战术各有天敌：挡拆怕换防、强打怕包夹、空切怕联防，
唯独"巨星球的"无法被克制——但 3 点体能的代价不菲。

## 运行

```bash
python -m hooprogue              # 终端流式模式（唯一前端）：全部输出打字机化
python -m hooprogue --auto       # 观战：AI 教练流式解说并决策
python -m hooprogue --speed 0.3  # 流式速度倍率（0 = 瞬时，测试用）
python -m hooprogue --manual     # 战术手册
python -m unittest discover -s tests
python tools/balance.py 100      # 平衡性标定
```

### 直播节奏

终端里所有输出都是打字机流式，速度由比赛事件决定——节奏本身在叙事：

* 我方出手结果逐字缓慢揭晓，悬念停在"✓ +2"出现之前；
* 对方得分更慢、停顿更长，沉重感；
* 打铁、失误、防守成功中速急促，连续攻防像快节奏的文字实况；
* 节末、骤死、BOSS 登场、赛前抉择之前刻意放慢铺垫；
* 菜单与分隔线瞬时，不打断输入。

表情只保留极少量功能用途，正文用文字符号（▶ ◀ ★ ✓ ✗）与缩进区分角色。

## 技术难点与取舍

| 问题 | 本作的做法 | 常见做法 | 为什么不用常见的 |
|---|---|---|---|
| 博弈信息结构 | 意图公示 + 演技（噪声 + 交换最可能两项） | 完全隐藏信息 | 公示意图把运气从信息里剥掉，策略可推理；演技再给高阶对手加回不确定性 |
| 克制关系 | 单一 MATCHUP 表 + 推导函数，AI/手册/UI 共用 | 各处硬编码 | 单一数据源防不同步；新增战术只改表 |
| 数值平衡 | balance.py 批量自动对局，固定种子统计逐场胜率 | 手感调参 | "第1场 83% → BOSS 62%"的曲线可复现；曾因统计口径写错误判难度，工具化后这类错误会被抓住 |
| 终端直播 | TermStreamer 按行内容推断节奏（得分慢、普通快） | curses/rich 全屏 TUI | curses 在 Windows 需第三方包；打字机在任何终端可跑，"滚动直播"符合实况感 |
| 逻辑与表现分离 | 比赛逻辑纯函数化，输出层只是另一个前端 | 逻辑与渲染耦合 | 测试直接喂输入收集输出；换前端不动逻辑 |

早期的 tkinter 图形前端已移除以保持极简（需要时可从 git 历史找回），
终端流式模式是唯一且完整的前端。

## AI 教练

观战模式下，AI 教练像大模型一样流式输出思考过程（终端以竖线侧栏
`  |` 标记）——但没有任何 API：`narrate.rank_*` 期望值函数既是它的
决策依据也是解说词的数据源，全部来自真实对局状态，同种子同解说。

## 平衡性

100 局自动对局（AI 全知决策的基准线）：第 1 场胜率 83%，
此后 72% → 73% → 66% → BOSS 62%，夺冠率 18%。人类读播报会
更难，实际难度高于上表。数值集中在 `plays.py` / `opponent.py`。
